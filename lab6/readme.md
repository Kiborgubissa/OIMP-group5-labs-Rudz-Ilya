# Лабораторная работа №6 — Совместная сортировка двух массивов

## О работе

Лабораторная работа выполнена коммандно. Каждый участник реализовал свой алгоритм сортировки,
после чего два отсортированных массива сливаются в один общий (тоже отсортированный).

| Участник | Что делал |
|----------|-----------|
| **Матвиец Артём** | сортировка пузырьком (для массива 1) |
| **Смальцев Никита** | сортировка вставками (для массива 2) |
| **Рудь Илья** | слияние массивов |

Так как каждый предлагал свой алгоритм и реализовывал его отдельно, итоговая
задача получилась «составной»: массив искусственно разбивается на две подзадачи,
каждая решается своим методом, а результат объединяется слиянием.

Дополнительно сделана **демонстрационная версия** с пошаговой визуализацией:
видно, что происходит на каждом шаге обеих сортировок и самого слияния.

## Постановка задачи

1. Пользователь вводит **массив A** из `n` целых чисел.
2. Пользователь вводит **массив B** из `m` целых чисел.
3. Массив **A** сортируется **пузырьком**.
4. Массив **B** сортируется **вставками**.
5. Два отсортированных массива **сливаются** в один общий, тоже отсортированный,
   за один проход (алгоритм слияния двух упорядоченных последовательностей).
6. Результат выводится на экран.

## Как работает `arrayTask.cpp`

Программа разбита на небольшие функции — по одной на каждую «роль»:

- `kol()` — спрашивает количество элементов первого массива, проверяет, что `n > 0`.
- `vvod(n, arr1)` — читает `n` чисел в массив A.
- `sort1(n, arr1)` — **сортировка пузырьком**:
  двойной цикл, на каждом проходе самый большой элемент «всплывает» в конец.
  Сложность — O(n²).
- `InputArray2()` — читает второй массив в `std::vector<int>` (размер известен только в рантайме).
- `Sort2(arr2)` — **сортировка вставками**:
  каждый следующий элемент «вставляется» в уже отсортированную часть сдвигом.
  Сложность — O(m²), но на почти отсортированных данных работает за O(m).
- **Слияние** (в `main`) — классический двухуказательный алгоритм:
  пока оба указателя `i`, `j` не дошли до конца,
  сравниваем `arr1[i]` и `arr2[j]` и кладём меньший в `result`;
  после выхода из цикла «добираем» остатки одного из массивов.
  Сложность — O(n + m).

### Что важно в реализации

- Массив A — **динамический** (`new int[n]` / `delete[]`), потому что размер неизвестен на этапе компиляции.
- Массив B — **`std::vector<int>`**, потому что вектор сам следит за памятью и его удобно возвращать из функции.
- Массивы должны быть **уже отсортированы** к моменту слияния — это ключевое условие алгоритма слияния,
  без него двухуказательный проход даст мусор.
- Знак `<=` в сравнении `arr1[i] <= my_array[j]` — не случайный: он обеспечивает **устойчивость**
  (при равных элементах первым идёт элемент из A), хотя для задачи это не критично.

## Как работает `arrayTaskDemonstration.cpp`

Тот же алгоритм, но **с визуализацией** каждого шага. Добавлено:

### Отрисовка

- `clearScreen()` — очистка экрана через ANSI-последовательность `\033[2J\033[H`
  (работает в Windows 10+, Linux, macOS; на старых Windows потребует включения
  `ENABLE_VIRTUAL_TERMINAL_PROCESSING`).
- `drawBars(arr, hl1, hl2, title)` — рисует массив в виде горизонтальных полос `*`
  и подсвечивает красным текущие сравниваемые индексы.
  Масштаб по максимальному значению, чтобы столбики не вылезали за экран.
- `drawMergeVisual(arr1, n, i, arr2, j, result, k, title)` — специальная отрисовка **для слияния**:
  показывает сразу **три блока** — массив A, массив B и накапливаемый результат.
  Красным помечены текущие указатели `i` и `j`, зелёным — уже добавленные в результат элементы.

### Паузы

- `sleep_ms(ms)` — простая пауза через `clock()` без потоков
  (в учебной программе достаточно; в реальном коде использовали бы
  `std::this_thread::sleep_for`).

### Визуализация внутри сортировок

- **Пузырёк**: перед каждым сравнением подсвечивается пара `(j, j+1)`.
  После обмена — снова перерисовка, чтобы было видно, как значения «переехали».
- **Вставки**: на каждой итерации показывается, какой элемент «берём»,
  а при сдвиге — где сейчас идёт перекладывание.
- **Слияние**: после каждого выбора элемента из A или B перерисовка,
  чтобы было видно, как «ползёт» указатель и наполняется результирующий массив.

## Алгоритмическая часть

| Этап | Сложность (время) | Сложность (память) |
|------|-------------------|--------------------|
| Пузырёк (массив A) | O(n²) | O(1) |
| Вставки (массив B) | O(m²) | O(1) |
| Слияние | O(n + m) | O(n + m) на результат |
| **Итого** | **O(n² + m²)** | **O(n + m)** |

Основная идея лабы — показать, что **две независимые сортировки** делают работу параллельно
(в смысле «каждый свою часть»), а **слияние двух уже отсортированных массивов** — линейная операция.
Именно на этом принципе построена сортировка слиянием (Merge Sort):
разбить → отсортировать части → слить.

## Возможные улучшения

- Добавить **флаг «были ли обмены»** в пузырёк — ранний выход на почти отсортированных данных.
- Заменить ручное `new int[n]` на `std::vector<int>` — не придётся писать `delete[]`.
- Вынести сортировки и слияние в отдельные `.cpp/.h`-модули (для лабы одного файла достаточно,
  но при желании легко разделить).
- Добавить **юнит-тесты** для краевых случаев:
  пустые массивы, массивы из одного элемента, уже отсортированные, обратно отсортированные,
  с дубликатами и отрицательными числами.
- В `arrayTaskDemonstration.cpp` — **неблокирующий sleep** через `<thread>/<chrono>`,
  чтобы не грузить процессор пустым циклом `while (clock() < ...)`.

## Ограничения

- Ввод ожидает **целые числа** через пробел / перевод строки; дробные и мусорные символы не валидируются
  (в учебной постановке это допустимо).
- При `n <= 0` программа печатает «ошибка» и возвращает `0` — дальше код не выполняется,
  но освобождения памяти в этой ветке нет (утечки не будет, потому что `new` ещё не вызывался).
- Визуализация рассчитана на **терминал с поддержкой ANSI-цветов**
  (Windows 10+, Linux, macOS). В старом `cmd.exe` цвета могут не отобразиться —
  тогда используйте `Windows Terminal` или включите виртуальный терминал вручную.
